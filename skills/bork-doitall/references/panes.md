# Agent Execution

For `execution_driver: hc`, follow the separate [hc contract](hc.md) for discovery, hidden interactive launches, turn acknowledgment, reuse and final shutdown. It supersedes exit-after-report runner instructions only for hc. Verified hc membership precedes every row in the legacy selection table below.

## CLI Profile

Detect executables by invoking their documented version/help commands through structured argument arrays in the current execution environment. Do not branch on OS names, assume Unix paths, or require `which`, `command -v`, Bash or a POSIX socket. PowerShell command resolution or other host-native discovery is valid. Check the inherited Herdr variables through the host's environment API. Verify capabilities and connectivity from actual results; installation alone is insufficient. Keep paths, environment, PHP, Git, the provider CLI and the multiplexer in the same execution environment. WSL/MSYS/SSH are not automatic substitutes: use them only when they are the invoking environment or explicitly authorized.

Select the new batch driver from the invoking process's verified session membership, before checking workflow capacity or displaying the plan. Use the shared read-only `php <skill>/scripts/environment.php <absolute-input-json>` helper. Its input contains `capabilities`, keyed by driver, with `supported: true` and compact `evidence` after the owner verifies all applicable checks below; otherwise supply `supported: false` and a concrete `blocker`. The helper inspects inherited membership signals, recovers a unique local Codex frontend when needed, probes the resolved contexts, then validates the selected driver's supplied capacity evidence. It never creates sessions or selects another driver after failure. Run discovery before the preview and refresh it after `go`; persist its complete `result` as `environment_selection` alongside the matching `execution_driver`.

When the user reports running inside hc, Herdr, tmux or Screen, include `expected_environment: "herdr"` or `"tmux"` or `"screen"` in the helper input. This guards against hidden context; it does not force driver selection. Run discovery outside the sandbox through the host's supported execution when permitted: a sandbox may hide variables, sockets and process ancestry. Empty tool variables alone do not establish that the invoking terminal is outside a multiplexer.

For a detached Codex daemon on Linux, the helper recovers context from exactly one same-user interactive Codex frontend whose working directory matches discovery's working directory. With `CODEX_THREAD_ID` present this also runs automatically when terminal variables are absent. It excludes backend and noninteractive worker processes, copies only the documented hc/Herdr/tmux/Screen caller variables into subprocess environments, verifies the live API/socket identity and the pane shell's ancestry against the frontend PID, and records the frontend PID, process start time and cwd. This is a unique local caller inference, not a thread-ID association supplied by Codex. Multiple matching frontends, stale identities or unverifiable contexts block selection. Do not select by focused pane, latest process or arbitrary environment copying. On hosts without procfs, use inherited context; a reported detached caller remains blocked. `codex --no-daemon` is an alternative when the installed CLI supports it; do not stop the shared daemon.

When recovery is recorded, run all later terminal commands from the saved frontend cwd through `php <skill>/scripts/environment.php herdr <command-arguments>` or `php <skill>/scripts/environment.php tmux <command-arguments>`. Each call rechecks frontend identity and live membership before execution. The tmux wrapper supplies the verified socket via `-S`; omit socket options from its arguments. Herdr returns the normal CLI JSON, and tmux returns normal command output. Pass arguments as an array, including an entire runner command as one argument. These wrappers grant no additional mutation authorization and use bounded command waits; reconcile any uncertain mutation before retrying. Keep using absolute worktree/job paths when discovery's cwd differs from a worker's cwd. For the tmux launcher helper, supply the resolved context's `socket` as `socket_path` in every launch/inspect/cleanup input so it uses the verified server even when the backend lacks `TMUX`.

| Verified Herdr membership | Verified tmux membership | Driver |
| --- | --- | --- |
| Yes | No | `herdr` |
| Yes | Yes | `herdr` |
| No | Yes | `tmux` |
| No | No | `screen` when verified Screen membership is active, otherwise `native` |

Installed executables alone never establish membership. Missing signals mean inactive; any partial, stale, unreachable or unverifiable explicit context blocks selection, including an invalid lower-priority context. Herdr uses its documented `HERDR_ENV`, caller pane and inherited socket, with live pane/process reads. Tmux uses `TMUX` and `TMUX_PANE`, the exact inherited socket via `-S` (including named sockets), and live server/session/pane identities. Both verify the pane shell is an ancestor of the invoking process or the recovered frontend, so copied environment values cannot identify an unrelated live pane. The helper requires a working `ps -eo pid=,ppid=` interface for this proof; if unavailable with explicit terminal context, report that verification blocker. Never forge environment values or inspect the user's focused Herdr session from outside a managed pane. Do not save unrestricted environment or process dumps.

Check capacity separately for the selected driver, preserving authentication, host identity, Git, PHP, permissions and selected model checks:

- `herdr`: compatible inherited session API and [Herdr execution contract](herdr.md), the same host's terminal CLI, one native delegation level and two simultaneous slots per master CLI session, plus two concurrent terminal workers for goodcode.
- `tmux`: the verified live context, the same host's usable terminal CLI, one native delegation level and two simultaneous slots per master CLI session, plus two concurrent terminal workers for goodcode.
- `screen`: the [GNU Screen contract](screen.md), verified live session/window ancestry, the same host CLI, one native delegation level and two simultaneous slots per master CLI session, plus two concurrent terminal workers for goodcode.
- `native`: coordinator → master → goodcode → review/fix, three delegation levels and at least `1 + 4 * max_concurrency` simultaneous slots. Goodcode needs two concurrent native workers. No multiplexer or terminal CLI is required.

Each master delegates prify/goodcode as native subagents. Goodcode retains the recorded batch driver for its review/fix workers under [worker execution](../../bork-goodcode/references/execution.md). Native capacity never outranks active tmux. A selected-driver capability failure blocks that driver without switching hosts, drivers or concurrency. Resume existing approvals with their recorded driver, even when the invoking environment changes; reconcile inaccessible recorded resources before any launch. An intentional driver change requires a revised preview and `go`.

Goodcode selects worker models and reasoning effort under its own [effort tiers](../../bork-goodcode/references/effort-tiers.md) policy. Master and prify use the host's configured defaults. Do not forward credentials or permission-bypass flags. Use normal local authentication and permissions. A pending approval still occupies the target slot.

Use role briefs instead of personas: the coordinator owns batch scope, scheduling and final status; each master owns one target's phase gates and promotion; prify creates the draft PR; goodcode owns review cycles and fixes; review reports findings; fix changes code for blocking findings. Give each agent only its target identifiers, authority, required skill and durable record paths. Escalate decisions outside that role to its parent agent.

For native mode, spawn masters through the host's documented agent mechanism. For hc, Herdr, tmux or Screen, build and record the CLI argument array once from local help. Each master brief explicitly loads the absolute `SKILL.md`, target brief, role and result path. Do not rely on slash-command discovery across hosts. All native subagents receive compact task briefs and paths to durable records, not the full batch transcript. Use a fresh or minimal context when the host supports it. Reuse verified role-bound subagent sessions across cycles when supported by [worker session reuse](../../bork-review/references/reuse.md); otherwise start fresh from compact records. Reconcile an interrupted run before resuming or replacing an agent. Never replay uncertain mutations.

Inspect the agent tree through the host's agent interface. Codex CLI exposes `/agent`; Claude Code exposes its agent panel. In native mode the coordinator's agent tree contains every target master. In Herdr mode, use the recorded pane and the navigation commands in [Herdr execution](herdr.md). In tmux mode, attach to a master's session to inspect that master's tree. The exact controls depend on the installed host.

## Scheduler and Terminal Launchers

Before each launch, apply [extra instruction routing](instruction-routing.md) and include the target's instruction paths in its brief. The master forwards role-specific paths to each subagent and verifies coverage. Record intent and a unique result path before spawning a native master; save its returned agent ID immediately. The master does the same for each prify and goodcode child, using a distinct path for draft and ready goodcode. Reconcile each uncertain spawn and result before trying again; a vanished agent or lost final message never justifies a duplicate child.

`php <skill>/scripts/tmux.php schedule <absolute-input-json>` requires PHP CLI 8+ but does not invoke tmux; use it for read-only previews with every driver. During execution, call [batch runtime](batch-runtime.md) `reserve` for atomic scheduling and blocker persistence. The `launch` action is only for tmux and requires a usable tmux command interface and the selected executable, regardless of OS. The `run` action executes the immutable job with inherited terminal streams and publishes process exit evidence; both Herdr and tmux use it without duplicating the runner. It does not invoke tmux itself. For Herdr pane creation and submission, follow [Herdr execution](herdr.md). The helpers return compact JSON and a nonzero exit on failure. They never call GitHub, delegate work, merge PRs, delete worktrees, or infer phase success.

`schedule` accepts `{"max_concurrency":1,"targets":{"id":{"status":"queued","depends_on":[]}}}`. The normalized target map may contain any number of supplied roots and verified sub-issues. `max_concurrency` defaults to `1` and accepts integers from `1` to `3`; values above `1` require an explicit user request. It returns active count, launch IDs up to remaining slots, waiting IDs, and a `blocked` map. Each blocked entry names either `dependency_blocked` with the immediate prerequisite or `dependency_cycle` with cycle IDs. The batch runtime applies this same scheduler when reserving. Re-run `reserve` after terminal state changes; a graph with no launch or active nodes must have every queued target classified as waiting on an active prerequisite or blocked.

For tmux, `launch` accepts `role: master`, `review` or `fix`, an existing absolute `cwd`, an absolute immutable `job` JSON path, and a unique `session_name`. The job contains `argv` (absolute executable followed by individual arguments) and a unique `exit_record` path. An exit record is process evidence only, never a skill result. Set `socket_path` to the verified absolute socket path for the batch; the helper uses `-S`. The alternative `socket` selects a named tmux server with `-L` for isolated fixtures. Never supply both, and keep the selection consistent for the batch. Other roles are rejected by the helper. Supply `shell: posix`, `powershell` or `cmd` matching the actual destination shell, verified from tmux configuration and installed shell help. Do not infer it from the coordinator's OS. Legacy inputs without `shell` retain POSIX quoting; new launches must set it explicitly. The shared command builder quotes for the destination shell independently of the OS running PHP, and rejects unsupported shells or unsafe cmd expansion characters before creating a session.

For tmux, use `do-<repo>-<kind><number>` for session names, for example `do-wlm-i123` or `do-wlm-p456`. Choose a lowercase repository abbreviation of 2 to 8 letters or digits and reuse it throughout the batch. `i` identifies a canonical issue target; `p` identifies a canonical PR target. Omit batch IDs, timestamps, titles and agent names. If the name belongs to another run, append the smallest available suffix starting with `-2`. Persist the name and keep it through all phases. On resume, reuse the recorded session after reconciling a partial launch.

For Herdr and tmux, prepare separate immutable job and launch files per attempt. Save launch intent before invoking the helper and returned session/pane IDs immediately afterward. In Herdr mode, save the created pane ID before submitting the runner command. If launch fails midway, inspect the recorded pane or named session before retrying. Never reuse an exit-record path.

## Lifecycle and Recovery

Each active target has one master agent. The master delegates prify if needed, then draft goodcode if the PR is draft, and ready goodcode unless approved `NOREVIEWER` skips it. Goodcode owns its worktree and review/fix subagents. The master owns phase transitions and promotion; the batch coordinator owns queue state. Do not launch a second master for the same target while the first remains active.

Record native agent IDs, role/model bindings, run directories, phase intent, acknowledgment and final results in durable records. A child agent's final message or disappearance is insufficient without its required durable result. On a blocker, safely stop and reconcile active descendants before ending the master or releasing the slot. Keep a master available when it awaits user input.

In native mode, use the master's agent ID and host status/result mechanisms for bounded waits and resume. Reconcile its durable target result and possible mutations before marking it terminal. A final message or vanished agent alone never proves target success.

In Herdr mode, follow [Herdr lifecycle and recovery](herdr.md#lifecycle-and-recovery), preserving pane identity, output, job and exit evidence before closing an owned stopped pane.

In tmux mode, use the returned master pane ID for inspection and cleanup. Poll `#{pane_dead}` and role records with bounded waits. For an owned dead master pane, capture scrollback, `#{pane_dead_status}`, its unique exit record and job identity; reconcile its durable target result and possible mutations; then close the pane even for blocked or failed outcomes. A dead or vanished pane or successful CLI exit alone never proves target success. Never close an unrelated tmux pane/session.

For tmux, save a `tmux attach-session -t <session>` command, with the selected socket when applicable, while the session exists. After any master exits, retain diagnostics in durable records.

## Surfacing Interactive Attention

An interactive blocker is a question, confirmation or permission prompt addressed to the operator in a master or descendant's status, or a live agent that has produced no progress beyond its expected step. Documented automatic waits, such as the selected reviewer gate, are excluded.

At the first detection, the master reports a child blocker to the coordinator with the target, role, agent ID and exact prompt. The coordinator immediately messages the user with that prompt and the host's agent navigation path; for Herdr, include the recorded pane ID and focus/attach commands from its execution contract; for tmux, include the master attach command and pane ID. It also inspects master status for direct prompts. Continue independent targets and avoid repeated notifications for the same unanswered prompt. Do not treat a child waiting for approval as ordinary silent progress.

Maintainers: run `python3 <skill>/scripts/tests/test_batch.py` for offline transition and interruption tests, and `python3 <skill>/scripts/tests/test_tmux.py` for isolated queue and real-tmux smoke tests. They launch harmless local fixtures, never an AI or GitHub action. Python is only a test dependency.

For Screen discovery, launching, navigation, lifecycle and resume, follow the [GNU Screen contract](screen.md). Screen follows tmux in selection priority. Preserve any recorded driver on resume. The shared runner is used by all three terminal drivers.
